# 智能眼镜 · 软件部分

> 戴上之后，它看见的东西会变成一句话说给你听。
>
> 「前面有人，两米左右。左边有把椅子。」

这是**软件那一半**：看见 → 看懂 → 说出来。
硬件（ESP32-S3 + 摄像头 + 骨传导）只负责采画面和放声音，跟机器人「汤圆」是同一套结构。

---

## 它怎么跑

```
摄像头 ──▶ NanoDet（3.6MB，80 类）──▶ 多帧确认 ──▶ 距离估计 ──▶ 一句话 ──▶ 语音
                    │                      │            │
                 检测框              过滤误报      h_px → 米
```

```bash
python3 setup_models.py                    # 下模型（3.6MB，只下一次）

python3 glasses.py --image 照片.jpg         # 看一张照片
python3 glasses.py --camera 0               # 摄像头实时（开窗）
python3 glasses.py --camera 0 --speak       # 实时 + 播报
python3 glasses.py --camera 0 --speak --record 演示.mp4
```

## 这个项目是怎么来的

代码是和 AI 一起写的。说清楚边界：

**我定的**

- 做"辅助"，不做"替代看路" —— 它只在你旁边小声说一句，不替你判断安全
- **宁可不说，不许说错**：这是整个项目的最高原则，其他都让位
- 砍掉：一开始想加文字识别（读路牌），模型选型没把握，先砍

**AI 写的**

- 实现代码、测试、文档初稿

**我验的**

- 每改一次都跑一遍真实照片和摄像头；报错了就查到底是模型问题还是代码问题

## 翻过的车

| 踩的坑 | 后来怎么办的 |
|---|---|
| 模型文件名写 `320`，**实际输入 416**，直接崩 | 改成从模型里读输入尺寸，不认文件名 |
| 六个输出的顺序不是交替的，按 `[::2]` 取会错位 | 按通道数分（80 是分类头，32 是框头），不靠顺序 |
| `exp` 溢出成 `inf`，`inf/inf=nan`，框全废 | 减最大值再 exp，再把 nan 清掉 |
| 一张人像上把**帽徽认成钟、姓名牌认成手机** | 加了多帧确认 + 面积门槛 + 类别白名单 |


## 三个设计决定

**① 多帧确认，宁可不说**

小模型在正式场合会出错 —— 实测一张人像上，它把帽徽认成"钟"、把姓名牌认成"手机"。

对看不见的人来说，**报错比不报危险得多**（他可能因为一句"前面有台阶"而踏空）。
所以：置信度 ≥ 0.45、面积 ≥ 画面 0.6%、**连续 2 帧看到**才算数。

**② 只说最近的三件事**

报十个框等于没报。取最近的三个，去重同类，先说方位再说距离。

**③ 距离只说区间**

`d = f × H / h` 这个公式里，`H`（这个类别多高）本身是**假设**的 —— 一个杯子 8cm 还是 12cm，误差就 50%。
所以对外只说"大概一米""两米左右"，绝不说"1.23 米"。

## 现在能做什么

| 能力 | 状态 |
|---|---|
| 80 类常见物体检测 | ✅ CPU 上几十毫秒一帧 |
| 方位（左/中/右） | ✅ |
| 距离（区间） | ✅ 有尺寸先验的类别 |
| 多帧确认去误报 | ✅ |
| 太近的东西单独报警 | ✅ 「小心，人离得很近」 |
| 语音播报 | ✅ 在线音色，失败退回本机 |
| 文字识别（读字） | ❌ 还没做（见下） |

## 还没做 / 做不了的

1. **文字识别**（读路牌、读书）—— 需要 OCR 模型（ppocr + crnn，约 8MB），
   接口留好了但还没接。
2. **方向感**（"在你左前方 30 度"）—— 现在只有左/中/右，需要标定摄像头朝向。
3. **台阶、坑、透明玻璃** —— 单目摄像头基本无解，得靠深度相机或超声波。
4. **真机没验过** —— 这里是 Mac 上跑的；ESP32-S3 上要换成 C 固件
   （ESP-DL 跑 nanodet 的 int8 版本），或者走"板子采画面 → Wi-Fi 传回 Mac 推理"。
5. **距离误差** ±30% 以上，别当尺子用。

## 搬到眼镜上要做什么

| 现在（Mac） | 眼镜上 |
|---|---|
| USB 摄像头 / cv2 | OV2640 + 拍照 |
| `glasses.py` 主循环 | ESP32 定时抓帧，POST 给 Mac |
| `speak.py` 的 `say` | I2S 功放 + 骨传导 |
| — | 电池、按键、状态小屏 |

**采传分离**是刻意的：ESP32-S3 跑 int8 量化后的 NanoDet 大概 3—8 fps，
而"传回 Mac 推理"能到 15—30 fps。先跑通再优化。
